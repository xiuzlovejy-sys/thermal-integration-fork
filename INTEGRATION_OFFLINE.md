# Offline integration fork — dry-run boundary

Base: fixed `thermal-review/tunecc-1.17.5`, copied to this separate fork. Four C99 files in `ChargeLimiter/OfflineAdvisory/` are byte-identical snapshots of sibling `thermal-native-core/{thermal_policy.c,thermal_policy.h}` and `thermal-native-capacity/{native_capacity.c,native_capacity.h}` as of this fork. Other sibling projects are untouched. `CLOfflineAdvisory.mm/.h` is a standalone daemon-side *candidate*, deliberately absent from every Xcode target and absent from `daemon.mm`. No charging policy, notify, filesystem configuration write, app UI, installation or hardware operation was added. Never run upstream build/install scripts for this experiment.

## API / UI data contract (proposal; not yet exposed on HTTP)

`+[CLOfflineAdvisory validateSettings:]` returns `{valid: bool, error: string, schema: 1, dry_run: true, actuator_available: false}`. `-observeBattery:settings:monotonicNow:monotonicSampleAt:ownership:` returns `{status: 0, schema: 1, dry_run: true, actuator_available: false, source: "offline_advisory", sample_clock: "caller_monotonic", ownership_verified: false, physical_state_verified: false, thermal: {enabled, level, has_request, proposed_level, action, reason, age_s}, capacity: {enabled, held_latch, suggestion, reason, evidence, age_s}}`. `age_s` is a number or JSON null. `action` is `tp_action` enum (0 none, 1 propose-only, 2 propose-release-only, 3 manual-stop-review); levels are 0 off / 2 light / 3 moderate. `held_latch` is *internal memory*, never charging state; `suggestion` is `none|stop-review|resume-review` and `evidence` remains `unverified (mock only)`. `has_request` and `proposed_level` are proposals, never commands. UI MUST label both as simulation, must not claim device safety or effective charging control, and must never use these as an actuator's input. Invalid settings return `{status:-422,error,dry_run:true,actuator_available:false}`, wipe local policy memory, and do not run either core. This diagnostic envelope is intentionally independent of upstream `get_conf` / `get_bat_info`: neither API is changed or augmented.

Settings object (both policy objects required, unknown keys rejected, disabled by default in the example):

```json
{"thermal":{"enabled":0,"rise_light":35,"rise_moderate":39,"fall_light":33,"fall_moderate":36,"emergency":44,"min_hold_s":60,"max_age_s":15},"capacity":{"enabled":0,"max_percent":80,"resume_percent":75,"max_age_s":15}}
```

`enabled` must be numeric 0/1. Omitted thresholds in each *present* policy object use core defaults; all supplied values must be finite. Thermal temperature thresholds each in [-20,90], hold [0,86400], age [0,3600], and strict core ordering `fall_light < rise_light < fall_moderate < rise_moderate < emergency`. Capacity max integer [6,100], resume integer [5,99], resume < max, age [0,3600]. Validation rejects strings, nulls, NaN, infinities, fractional percentages, unknown keys and missing objects/enable fields; the exact error string is diagnostic, not stable for machine parsing. Any config change recreates both latches (no cross-config carryover). Disabled capacity clears latch; disabled thermal masks all proposed requests and sets `paused` to avoid warming transitions. Do not map this object to legacy `set_conf` or persist as live preferences.

Inputs: `battery` is a read-only snapshot with integer percentage `CurrentCapacity` [0,100], centi-Celsius `Temperature` [-2000,9000], and both numeric bool `ExternalConnected` and `ExternalChargeCapable` true for a conservative plug hint. Missing/malformed SOC or temperature is passed as absent. `monotonicNow` and `monotonicSampleAt` must be seconds in the SAME caller-supplied monotonic clock domain; no timestamp is invented. `UpdateTime` is not accepted as this monotonic time. `ownership` is a mock string; only explicit `"ours"` lets the pure cores produce proposals. This does NOT assert real ownership: output always says `ownership_verified:false`. No verified thermal safety arbitrator exists: `thermal_safe=0` unconditionally, so capacity resume advice never appears while held. Incoming battery data and settings are not mutated. One instance must run on one serialized event stream; do not access concurrently. No implied power-source verification; iOS17 derived plug flags can flicker. Simulator console logging prints the result and should be privacy-reviewed before any deployment.

## Precise later hook (not implemented)

If separately authorized for a future simulation build, register the C files and `.mm` only in **daemon** targets with Foundation and C99 libm, keep dry-run guards and no actuator references, and insert `observeBattery:settings:monotonicNow:monotonicSampleAt:ownership:` after a successful `getBatInfoWithServ(serv, &bat_info)` in `ChargeLimiter/daemon.mm:onBatteryEvent` (currently lines 4756–4768), or after successful `getBatInfo(&bat_info)` in `refreshBatteryStateAndApplyPolicy` (4728–4739). The invocation must be outside/before `applyChargePolicy`, NEVER replace or pass results into it. Both event paths currently return early on `!g_enable`, so deciding whether to log master-off observations requires separate review. In the future *only* a new read-only diagnostic API branch in `handleReq` (starting ~5068) could serialize a cached immutable snapshot, without calling either step from the concurrent HTTP queue or returning it under `get_bat_info` implicitly. No hook or HTTP route exists now.

Existing upstream fields: `getBatSlimInfo` (~1027) keeps `CurrentCapacity`, `Temperature`, `ExternalConnected`, `ExternalChargeCapable`, `UpdateTime`, `CycleCount`, `DesignCapacity`, `NominalChargeCapacity`; `AppleRawMaxCapacity` falls back to `NominalChargeCapacity`. `applyChargePolicy` (~4494–4507) reads `CurrentCapacity`, divides raw `Temperature` by 100, and computes adaptor state via `isAdaptorConnect` to handle legacy inflow behavior. `get_bat_info` (~5294) returns a fresh battery snapshot plus existing `HoldActive`, `HoldTarget`, `PolicyState`, etc. These fields are *not* proof of ownership, trusted monotonic sample time, thermal arbitration, or physical effectiveness; do not substitute capacity mAh metrics for percentage SOC. This adapter deliberately does not read `adv_*`, `charge_above`, `charge_below`, `enable_temp`, or existing apply-status fields, and will not change their behavior.

## Local verification / limitations

```sh
D=/var/minis/workspace/thermal-integration-fork
cc -std=c99 -O2 -Wall -Wextra -Werror -pedantic "$D/ChargeLimiter/OfflineAdvisory/thermal_policy.c" "$D/ChargeLimiter/OfflineAdvisory/native_capacity.c" "$D/tests/offline_advisory/test_cores.c" -lm -o /tmp/thermal-integration-cores
/tmp/thermal-integration-cores
python3 "$D/tests/offline_advisory/test_contract.py"
```

This builds C cores only and checks two-stream behavior, invalid configurations, stale SOC, unknown ownership and resume denial; Python checks source-only isolation and build non-registration. iSH/Alpine has no Apple Foundation SDK or Objective-C++ compiler; `.mm` cannot be compiled here. Objective-C behavior, daemon linking, iOS runtime and hardware efficacy are NOT tested. No daemon/app integration or live user setting/API route is claimed. No event or HTTP policy state is persisted. Separate iOS SDK compilation, serialized callback analysis, battery freshness source, ownership lease, and independent thermal safety arbitration are prerequisites before even considering production integration; all device-write paths require explicit separate authorization and review.
